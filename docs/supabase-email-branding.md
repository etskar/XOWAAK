# Supabase Email Branding

The application already sends Supabase Auth links through XOWAAK callback routes. Sender identity
and email appearance are controlled by Supabase Dashboard, not by frontend code.

Manual Dashboard actions:

1. Open **Authentication -> Email Templates**.
2. Update **Confirm signup** and **Reset password** subjects and HTML using XOWAAK branding.
3. Keep the callback links generated by the application; do not replace them with a fake endpoint.
4. Open **Project Settings -> Auth -> SMTP Settings** and configure an approved sender such as
   `XOWAAK` only when a real SMTP provider is available.
5. Add the production and local redirect URLs under **Authentication -> URL Configuration**.
6. Send a real test email from the sign-up flow and verify the confirmation callback before calling
   email branding complete.

SMTP passwords, API keys, and service-role values must remain in Supabase/Vercel secret settings
and must never be added to this repository.
